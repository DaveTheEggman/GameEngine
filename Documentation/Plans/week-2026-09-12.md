## Beef UI line reviewed + the Raptor fixes it surfaced (2026-09-12)

Their 136 commits since 7f4efcf port the whole UI line: UI proper (every subsystem and
control, the markup loader, the five themes with the legacy builders), UI.Toolkit (bars,
property grid, colour/vector editors, curve canvas + timeline, floating panel, docking, node
graph, code editor, theme extension), Gamekit, Runtime host, Shell bridge, Viewport, VFS,
Resource, Application, and the sixteen-tab UISandbox on screen - plus a leak sweep under
LeakSanitizer across the earlier libs. Our own suites drove it (P0-P4 included: the
cascade, box model, transitions and flex-wrap cases all green on their side). New porting
method: Raptor source is copied into the tree under RaptorCode/ and STRUCK in the same
commit as its Beef port; Foundation is done except what is not being ported (Script, Luau,
Mcp.Script, Engine.UI.Script struck as such); the agent has started the Engine layer.
Notes addressed to Raptor, each verified in our code and FIXED here:
- QuaternionField's Euler decomposition put the arcsine on X; the forward composition is
  Z-Y-X so the middle axis (Y) takes it - compound rotations read back wrong and were then
  rewritten on the first keystroke. Fixed; helpers made public; round-trip test over six
  triples plus the control's three fields.
- GridView rebound every visible cell per layout pass and never pruned a positional
  selection when the data set shrank - both fixes ListView already carried. Mirrored, with
  the bind-count and prune cases.
- StyleSelector matched a compound state with ANY bit (`:hover:checked` fired on hover
  alone) while its doc said all flags. Now `HasAllFlags`; test with a state-injecting view.
- DockLayout deflated by the chrome but added back only the padding: a bordered dock
  measured short by the border. Fixed with a test.
- Timeline was never registered for selectors, so the toolkit sheets' Timeline block
  styled nothing and the hand-kept type count could not notice. Registered; the count is
  gone; a test asserts no rule of either fragment is UnknownType and that Timeline is styled.
- VGRenderer::Variant fell back to the flat pipeline when a BoxShadow blend variant failed
  to build (flat colour over everything around the box); it now skips. No test: the
  failure is not reachable headlessly.
- Suites mirrored that Raptor lacked: DragDropTests (7: potential/threshold, quiet press,
  enter/over/leave/drop, rejecting target, Escape, no data, mid-drag teardown) and
  TooltipTests (7: delays, leave, ancestor owner keeps the clock, provider first, no focus,
  interactive hit-testing, deleted target). Writing the tooltip suite found a Raptor gap:
  hit-test visibility is self-only, so a non-interactive tooltip's CONTENT still caught the
  pointer; the tooltip now disables interaction for its subtree unless interactive.
Left as they are, noted: ScrollView's axis asymmetry (vertical unbounded unless Never,
horizontal only when Always) is the intended document shape; UndoStack's `i32&` outputs
and RemoveView's advisory deleteChild flag are spelling, not behaviour; the sandbox tree
rows' hard-coded indent is cosmetic. ContentButton / DrawableView measure cases they added
are still ours to mirror.
UI.Tests 827, UI.Toolkit.Tests 237. Four lanes green.

## Two Beef notes outside the commit log (2026-09-14)

Found while searching for their WebGPU note: two Raptor-directed observations that live in
their SOURCE comments, not in any commit message.
- FIXED: PakFileSystem sized everything from the header without checking it against the
  file. It now refuses a table that is not inside the file past the header, a count the
  table cannot hold, an entry whose bytes lie outside the data heap, and any compression
  but the stored one. Five corruption cases (huge count, table past EOF, table too long,
  entry range past the heap, truncated inside the table) plus the untouched file still
  opening. The read loop never spun before (a failed read ends it), so this is hardening of
  what a corrupt entry could hand a reader, not a hang.
- Already fixed here: a compressed CUBE sizing its faces per texel (the upload sizes by
  block, with a test).
Their report that some of OUR WebGPU pixel probes fail on a size difference could not be
located in their tree or reproduced: every WebGPU half of Render.Backend, VG.Backend,
Engine.Terrain.Backend and Integration.TextureCompression passes here against Vulkan, and
RHI.TestSupport already unpacks WebGPU's 256-byte readback rows. Needs their exact test
name and message.
