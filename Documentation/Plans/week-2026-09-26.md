## The Sedulous sync of 2026-10-01: the map and the port order

99 Sedulous commits on `vnext` since the review baseline 710aec1e, head 773b2379 (branch
`polish` is the same commit). Fourteen port our own work (the Editor.Project split, the scene
format reference, the engine composition); the rest are Sedulous-led. Two of those features
have specs already in this tree (untracked until this sync lands them):
editor-lists-and-asset-slots.md and agent-playtesting-and-asset-creation.md, both "LED BY
SEDULOUS, ported here from its commits"; scene-authoring-tools.md was written there for this
side to build first. The map was made by five read-only reviews, one per theme; what follows is
their port order, merged. Each item is one commit with its tests, clang and gcc green, the five
lanes at the end of each group.

### Group 0: bugs in our own tree the review found (first)

1. Http/Net: the MCP host binds every interface; bind loopback by default (Sedulous dd1602b6).
2. UI.Toolkit docking: a closed page's panel is only hidden (page panels carry a persistence id,
   `Docking.cppm:1784`); destroy it on close and detach its content before the page dies, on
   all three close paths (0ad9064a + fc3c6e2f).
3. Editor.Project: opening a project drops `loadingDocumentId` and `renderMsaaSamples`
   (`Project.cppm:213-228`, a hand-kept field copy); one `ProjectSettings` copy, and the dist
   manifest and export roots carry the loading screen and the MSAA (fbf1a4ff).
4. Render: the tonemap display-encodes and the sRGB swapchain encodes again (and the editor's
   float viewports); encode once, scalar push-constant pads for WGSL, the screenshot and the
   thumbnail downscale encode after averaging (d27d0962 + 3eb405e1). Needs a visual check.
5. Engine.GameInstance: a script level load never destroys the scene it replaces, on both the
   async pump and the sync binding; one adopt-and-replace path, the destroy deferred when a
   script calls into its own scene (50bbab40).
6. Particles: a spawned one-shot bursts at the origin (simulated before transforms, slot
   position never reset) (bf6a6712).
7. Core: SchemaRecorder prints an f32 widened to f64 (0.10000000149011612); a float
   FloatToChars (from the review of our port 9a67f935).
8. The FNV offset basis: `HashBytes` and `HashText` use 1469598103934665603, not the standard
   14695981039346656037 (Sedulous fixed theirs in 80272182), and the scene format reference
   documents the standard one, so an agent computing an override hash from the docs gets the
   wrong value. Here type ids are built on the same hash, so changing the value rewrites every
   saved scene, project and cooked payload. RULED 2026-10-01: migrate to the standard basis
   (match Sedulous), regenerate every checked-in scene, project and cooked file, rehash
   PaperKid's overrides; projects outside the tree re-save from a build that reads them.
