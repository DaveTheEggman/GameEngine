## Seeded: script backend as a PROJECT setting (user punt 2026-08-18)

Origin: punted from the week-2026-08-15 work. Today the script backend is a
BUILD-TIME choice (OPTION_ENABLE_/OPTION_HAS_<backend> + SCRIPTLIB_* link
aliases, guarded by #ifdef - see the script-backend-gating memory). The ask is
to make it a PER-PROJECT choice instead:

- **Chosen at project creation**, stored in the project settings, changeable
  later in project settings.
- Gates **which script options the editor surfaces** (New-Script creators, the
  CodeEditView lexer, script-facade validation) to the selected backend, and
  **which VM actually runs** for that project.
- Changing it **likely needs a project reload** (the running VM + registered
  script surface are established at load) - decide reload-vs-live at design.

Open questions for week start:
- Interaction with the build-time gating: a project can only select a backend
  that was COMPILED IN (OPTION_ENABLE_ set). The setting is a runtime choice
  AMONG the enabled backends, not a way to enable a non-built one - the editor
  should offer only the built backends and message clearly if a project asks
  for one that is absent.
- Where the selection lives (ProjectSettings field + the project-create dialog)
  and how the editor's per-backend registration (currently all-enabled) becomes
  selection-driven.
- Migration: existing projects with no stored backend default to the current
  primary (whatever the build's default is).

## Seeded: mesh LOD (user schedule 2026-08-18)

Origin: user-requested for this week; the design is ALREADY WRITTEN and the
dependency approved - this is a SCHEDULING decision, not a design one. Full
spec: Documentation/Specs/mesh-lod.md (prepared 2026-08-15, meshoptimizer
vendoring USER-APPROVED). Read alongside asset-variants.md (sibling; LOD is
runtime-selected, NOT a per-platform variant).

Goal: distance/coverage-appropriate geometry so dense scenes (Sponza-class)
spend triangles where they read. Two sources, one wire: artist-authored LOD
meshes (`_LOD1`/`_LOD2` name convention) when provided, meshopt_simplify auto-
chains when not. LODs live INSIDE the cooked mesh product (shared vertices,
per-LOD index ranges) - components keep a single `Ref<StaticMesh>`. Runtime
selection at EXTRACTION by projected screen-coverage, per view, with a ~10%
hysteresis band; `MeshComponent.lodBias` + `forceLod` knobs.

Phasing (from the spec - pick how far to take it this week):
- **P0** - vendor meshoptimizer + run its vertex-cache/fetch/overdraw optimize
  on EVERY cooked static mesh. No wire change, a free perf win, and it pays for
  the dependency BEFORE LOD lands. Acceptance: identical rendering (pixel probe)
  + measured ACMR improvement logged by the cook test. (Low-risk starter.)
- **P1** - the LOD wire + authored-LOD name collapse + extraction selection +
  hysteresis + component knobs + mesh-page dropdown. Sidecar/asset version bump
  = the migration (pre-bump meshes load as 1-LOD chains).
- **P2** - auto-generation (meshopt_simplify chains at import, error-bound drop).
- **P3** - polish (shadow coarsest-LOD rule, debug LOD-tint overlay, per-set
  instanced selection).
- **P4 DEFERRED** (do NOT build): skinned LOD chains, per-instance LOD bucketing,
  cross-fade transitions, LOD-aware physics cooking (physics keeps cooking LOD0).

Scope note: v1 is STATIC meshes only. Tests per the spec (Geometry.Pipeline.Tests
wire/chains/compat, ModelImporter.Tests name-collapse/generation, a Foundation.
Render-side selection unit test for coverage math + hysteresis); both compilers;
pipeline targets stay UI-free.

## Seeded: bespoke-page Undo/Redo - Sound Cue blob commands + toolbar roll-out (user 2026-08-15/18)

Origin: UAT (user-confirmed 2026-08-15). Two related pieces:

1. **Sound Cue page edits do not undo/redo.** The page HAS the page toolbar
   (m_toolbar->Refresh syncs Save/Discard/Undo/Redo) AND the blob machinery
   (SnapshotAsset / ApplyAssetBlob, used today only for Discard), but every edit
   (slot pick/clear, mode toggle, the pitch/volume jitter fields) mutates m_asset
   DIRECTLY - nothing is pushed to Commands(), so Undo/Redo stay disabled. Fix:
   route each edit through a blob command exactly like the bus-layout page does -
   snapshot before, mutate, snapshot after, `Commands().Execute(EditSoundCueCommand(
   before, after))` with merge-by-key coalescing for scrubbed fields. The precedent
   is AudioBusLayoutEditorPage (EditBusLayoutCommand + SnapshotAsset, already working).
   Low effort - the snapshot/apply halves already exist on the page.

2. **Roll the page toolbar out to the bespoke pages that lack it.** Grounding
   (2026-08-18): pages that ALREADY carry the toolbar - material, animation-clip,
   animation-graph, particle, bus-layout, sound-cue, scene. Pages WITHOUT it that
   EDIT and should get it: collision-shape (Editor.Physics), plus any editing page
   still missing it (texture/image/game-ui/input - audit at week start). Pure VIEWERS
   (mesh, skeleton) have no re-authorable fields, so Save is a no-op and they need no
   toolbar - skip them. Bus-layout already has blob-command undo, so once a page has
   the toolbar its Undo/Redo works the moment its edits go through Commands().

Tests: per-page snapshot/undo/redo round-trip (a scrub coalesces to one step; undo
restores the before-blob) - the clip/graph pages already have this shape to copy.
