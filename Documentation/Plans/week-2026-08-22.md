## Seeded: AngelScript delegate funcdef surface is ad-hoc (Fable to look into, user 2026-08-19)

Origin: the game-ready-scripting2 P2-6 `button.onClick` seam (script functions as native click handlers
via `IScriptDelegate`; landed 2026-08-19). The native side is general - a reflected
`RefPtr<IScriptDelegate>` param is spelled `?&in`, so ANY funcdef handle is accepted and `Invoke`
marshals against the handler's actual params. The wrinkle is the SCRIPT side: to wrap a function into a
delegate handle, AngelScript needs a PRE-REGISTERED named funcdef, and the backend ships only two
ad-hoc shapes (AngelScriptScriptImpl.cpp, RegisterDelegateSurface):

- `ScriptDelegate` = `double ScriptDelegate(double)` - a confusingly-named, arbitrary double-in /
  double-out shape (it reads as THE delegate type but only fits that one signature).
- `Action` = `void Action()` - the common void no-arg callback (what onClick handlers use).

A handler of any other signature has no funcdef to wrap it, and using the wrong one (`ScriptDelegate`
on a void fn) fails at compile with "Invalid expression: stand-alone anonymous function". Luau has no
such limit (functions are first-class values). For FABLE to look into: a cleaner delegate-signature
scheme - a blessed set of funcdef shapes, an auto-registered funcdef per reflected delegate-param
signature, or at minimum renaming/documenting so `double(double)` is not the confusing default. NOT
urgent - `Action` covers PaperKid's void handlers. (Separate and already DONE 2026-08-19: the
delegate-callback `CurrentScriptContext` bug this seam surfaced - facades silently no-oped inside
AngelScript handlers - is fixed; `ExecuteDelegate` now brackets a `ScriptCallScope`, mirroring Luau.
This funcdef-surface cleanup is the only open item.) Relates to [[script-facade-call-syntax]].
