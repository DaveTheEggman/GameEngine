## PrefabSpawnSystem ported from the Beef side (2026-09-19)

Their eb4bc82f was the cleaner answer to a question we had open (how a script spawns a
prefab without the surface seeing the content database), and it exposed two defects in
ours, so it came over (c59ff8ec). A scene system in the full composition (module `prefabs`,
count 12) holds the content database + resource manager; DefaultApplication is an
ISceneObserver now and points every composed scene's system at them at SystemsReady, and
re-points live scenes when the database or the manager arrives later (both can land after
scenes exist). Spawn(prefab, position, rotation, parent) reads the payload, spawns it with
the database as the nested-payload resolver, places the root in the parent's space, binds
the spawned subtree only (new `SceneSystem::ResolveEntityResources(entity, manager)` hook,
`SerializableComponentManager` implements it, free `ResolveEntityResources(scene, root,
manager)` walks the subtree). Every failure is an invalid handle, never a partial spawn.
What it replaced: the recipe twice in DefaultApplication (script spawner lambda +
ResolveNetworkPrefab), NEITHER passing a nested resolver - a runtime-spawned template's
nested instances were silently absent for scripts and replication alike - and both
re-walking every ref in the scene per spawn. The script path lost three indirections:
`scene.spawn` reaches the scene's own system; `ScriptRuntimeBinding::spawnPrefab`,
`ScriptSubsystem::SetPrefabSpawner` and the live wrapper are gone. ResolveNetworkPrefab
stays (tested name) and delegates to the static SpawnInto.
Tests: PrefabSpawnSystemTests (placement under a parent with rotation + children,
subtree-only binding through a real ResourceManager, the NESTING regression, every failure
path); the six script spawn tests run the real recipe over a one-prefab database (the
fake callback seam is gone with the seam); SceneSurfaceTests pins 12 modules + presence.
Four lanes green, 153/153 each. Docs: text-scenes (the touch point), scripting,
game-instance, game-ready-scripting.
Kept our facade signature (`spawn(prefab, x, y, z)`); rotation + parent are on the system,
a facade overload can follow with a sample that needs it.

## Reverse-Z: the depth convention switched, properly (2026-09-19)

Approved last week, done in one commit (68006311). The inventory first: every projection
builder call site (18), every depth compare (24 non-test), every depth clear, every shader that
reads or writes depth (23 files), the shadow biases on both sides, the frustum extraction, the
unprojects (cascade fit, UI pointer ray, debug frustum), picking (the editor's mouse ray is
built from the FOV, convention-free), the LOD math (projection[1][1], convention-free), the
cluster slices (view-space, convention-free), and the tests that pinned the old numbers.
The convention has three homes kept in step: `core::projection` (constants, IsNearer,
IsBackground, LinearizeDepth, DepthAtDistance; the builders; the frustum), `rhi::depth`
(Nearer/NearerOrEqual/Farther, ClearValue, BiasAwayFromViewer with the flipped sign) and
`Data/Shaders/depth.hlsli`. RULE from here: never a literal 0/1 depth, Less/Greater, or raw
bias sign - name the helper, so a grep audits the convention. Consumers that reconstruct
through InvProj/InvViewProj (GTAO/SSAO/SSR/SSGI/decals) and the soft-particle projection
terms needed nothing.
Two things the full suite caught that the inventory missed: the UI world-panel pointer ray
hard-coded near 0 / far 1 (now the named constants), and one render-graph test passed a
literal clear. One thing the probe caught in itself: the first shadow scene saturated white, so
the "shadowed" plane read as bright ambient - probe scenes need headroom for a ratio to mean
anything.
Proof at the pixel (Render.Backend.Tests/ReverseZProbeTests, Vulkan + WebGPU + the cooked
WGSL pack): nearer wins with the background untouched; a red face 0.02 units in front of a
wall 900 units away is solid (the reason for the switch: under standard-Z that gap is ~1/25
ulp at depth ~1 and it z-fights); a sun's shadow reads lit beside the caster and dark behind
it, which needs the cascade ortho projection, the caster-side hardware bias sign, the sampler
compare and the receiver-side bias all to agree. MathTests pins the matrix, the closed-form
linearize round trip, the ulp claim and the frustum planes. Four lanes, 153/153 each.
For the Beef side: their Float4x4 builders, frustum and shaders are ports of ours and now
diverge; the three homes above are the porting list.
