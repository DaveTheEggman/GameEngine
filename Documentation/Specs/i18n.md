# i18n - foundation layer

**Status:** DRAFT v2 for review (Fable, 2026-08-23). v1 specced the whole
chain (asset/pipeline/subsystem/editor page) and got two things wrong on
user review: it wrapped the service in an engine SUBSYSTEM it does not
need, and it scoped localization to game text when the machinery must
serve the EDITOR's own strings too (Traktor localizes its editor through
the same I18N dictionaries as game text). This v2 specs ONLY the
foundation layer - the consumer-neutral core everything else will build
on. The asset/cook chain, the ownership/integration story (game host,
editor), UI `@key` resolution, the editor grid page, and the
charset-from-string-tables font bake are FOLLOW-UP SPECS, written after
this layer is reviewed and landed.

Reference: Traktor `I18N` (Dictionary + master-merge + Text/Format,
~800 LOC core) - audited 2026-08-23. Sedulous has nothing to port
(math-gap policy checked).

## Why no subsystem

Localization is state (tables, active language) + pure functions (resolve,
format). It has no per-frame update, no device, no scene hook - nothing a
Subsystem provides. Ownership is the CONSUMER's decision at integration
time: the editor owns an instance for editor strings; a game host owns an
instance for game text; a test owns one on the stack. Script exposure
(later spec) installs the owner's instance as a script-context service -
which never required a Subsystem either. Two instances in one process
(editor UI + embedded game) is a FEATURE, not a workaround.

## Module

`Code/Foundation/I18N` - module `foundation.i18n`, alias
`Foundation::I18N`. Depends on `foundation.core` ONLY. No resource, no
RHI, no UI, no messaging - a leaf, fully headless-testable. (The cooked
resource wrapper is `foundation.i18n.resource` in the follow-up spec;
this library never knows it exists.)

## Types

### StringTable

The authored/cooked unit: a set of locale columns over a set of keys.

- Data: ordered locale-id list (`en`, `de`, `pt-BR`, ...) + per-key row of
  per-locale UTF-8 text. Keys are dotted ids (`menu.play`) - plain
  content strings, one flat namespace, hash-indexed for lookup (String
  storage + hash map; NOT the TypeRegistry string-hash domains - those
  are for type identity).
- Missing CELLS are legal (a locale column may be sparsely translated);
  missing-ness is queryable (`HasText(key, locale)`) so tooling can
  report completeness. Empty string is a VALID translation, distinct
  from missing.
- Serializable (ISerializer, versioned per the strict-versioning rule) -
  the same body serves the XML asset source and the cooked product later.
- Mutable by design (Set/Remove/RenameKey/AddLocale/RemoveLocale): the
  editor grid and CSV import edit THIS type directly - no editor-side
  shadow model (the no-editor-data-in-runtime rule cuts the other way
  here: there is nothing runtime-only in a string table).

### Localization

The resolver a consumer owns. Borrows N tables, holds the active
language, answers text queries.

- `AddTable(const StringTable*)` / `RemoveTable` - borrowed, non-owning
  (owners manage lifetime; a follow-up resource wrapper keeps RefPtrs and
  feeds the raw tables in). Merge semantics: LAST table wins per key
  (Traktor appendDictionary override) - deliberate, so a patch/DLC table
  can override a base table. Duplicate detection is a TOOLING concern
  (cook-time warning, later spec), not a runtime one.
- `SetLanguage(StringView localeId)` / `Language()`. Setting the language
  fires the registered change callbacks (below). Setting an unknown
  locale is allowed (resolution just falls through the chain) - tables
  may hot-reload in later.
- **Resolution order** for `Text(key)`: active locale, then its
  dash-truncation parents (`pt-BR -> pt`), then the FALLBACK locale
  (constructor/`SetFallbackLanguage`, typically the development language,
  default `en`), then its parents, then MISS.
- **Miss policy: return the KEY ITSELF** + a once-per-key LOG_WARN
  (deduped by key hash). Visible on screen, greppable, and self-healing
  when the text lands. (Traktor returns caller-supplied default text
  instead; rejected - scattered defaults drift from the tables and hide
  gaps.) `Has(key)` for callers that must know.
- `Text(key) -> StringView` - a view into table storage (valid until the
  table mutates or is removed; consumers that cache copy - documented).
- Change notification is a PLAIN CALLBACK LIST:
  `u32 OnChanged(Function<void()>)` / `RemoveOnChanged(u32)` - the
  owner-held-token pattern from messaging, but NO bus dependency: this
  library stays a leaf. The consumer that has a bus (the game host)
  bridges the callback to its `languageChanged` event; the editor walks
  its re-resolve list directly. Fires on SetLanguage AND on table
  add/remove (hot reload swaps tables).

### Formatting

`Format(key, args) -> String`: resolve, then POSITIONAL `{0} {1}`
substitution. Positional (not sequential `{}`) because translations
REORDER arguments - the load-bearing i18n requirement core::Format's
sequential model cannot express, which is why this lives here.

- Args: Span<const Variant> restricted to the natural types (bool,
  i32/i64, f32/f64, String/StringView) - numbers render via core
  formatting, C-locale decimal point (locale-aware number formatting is
  explicitly deferred).
- `{{` and `}}` escape literal braces. A placeholder naming a missing or
  out-of-range argument renders LITERALLY (`{3}` stays visible -
  greppable, same philosophy as key miss).
- No plural rules, no gender, no date/currency - CLDR-class problems,
  deferred until a real game hurts (format args cover counts).

### Locale-id helpers

Free functions, no locale database: `ParentLocale("pt-BR") -> "pt"`
(empty when none), `NormalizeLocale` (lowercase language, as-authored
region - tolerant matching so `en-US`/`en_us` compare equal). BCP-47-ish
by convention; the library validates shape ("looks like xx or xx-YY"),
never membership.

## Explicitly NOT in this layer (follow-up specs, in order)

1. **Resource + pipeline**: `foundation.i18n.resource` (cooked
   StringTable product + factory), `I18N.Pipeline` (XML StringTableAsset,
   builder, CSV import/export, duplicate-key warnings, count tripwires).
2. **Integration/ownership**: who owns Localization in the game host and
   the editor, script surface (`loc` static view was v1's proposal -
   re-decided in that spec), `@key` resolution in UI documents +
   re-resolve on change, `languageChanged` bus bridge, project/editor
   language settings. EDITOR STRING CATALOG: how the editor's own UI
   strings adopt keys (Traktor-style) - its own discussion; nothing in
   this layer precludes or requires it.
3. **Fonts**: charset-from-string-tables bake option (CJK).

## Tests (land with the library)

- StringTable: set/get per locale, missing cell vs empty string,
  rename/remove key, add/remove locale, serialize round-trip + version
  gate.
- Localization: hit; miss returns key + warns ONCE per key; fallback
  chain `pt-BR -> pt -> fallback -> fallback-parent -> key` (each hop
  exercised); merge last-wins across two tables; RemoveTable un-shadows;
  language switch + table add/remove fire callbacks; token remove stops
  delivery; Text() view validity across a benign lookup.
- Format: each arg type; reordered placeholders (`{1} ... {0}` - THE
  i18n case); `{{`/`}}` escapes; missing-arg renders literally; format
  of a missing key formats the key itself.
- Locale helpers: parent chain, normalization equivalence, shape
  validation accepts/rejects.
