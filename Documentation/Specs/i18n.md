# i18n - game text localization

**Status:** DRAFT for review (Fable, 2026-08-23). Reference: Traktor `I18N`
(Dictionary + master merge + Text/Format bridges + CSV/XLSX dictionary
editor - ~800 LOC core, the value is in the tooling) - audited 2026-08-23.
Sedulous has no localization stack to port (math-gap policy checked).

GOAL: localized GAME text - authored string tables, cooked like any asset,
resolved at runtime by key through one service, reaching UI documents,
gamekit widgets, and scripts, with a translator-friendly editor page and
CSV round-trip. The EDITOR ITSELF STAYS ENGLISH - this module is product
text only (deliberate; revisit only if the editor ever ships to
non-English users).

## Decisions (proposed - user may overrule any)

1. **Keys are dotted UTF-8 ids** (`menu.play`, `hud.lives`) resolved
   through the StringHash path (Runtime type domain rules do not apply -
   these are plain content keys, one flat namespace per project). Lookup
   MISS returns the KEY ITSELF (Traktor returns default-text; returning
   the key makes missing text visible on screen and greppable - the
   standard game-dev choice) plus a once-per-key LOG_WARN.
2. **One StringTable asset carries ALL locales** (rows = keys, columns =
   locales). Translators and the editor grid see everything side by side;
   diffs stay in one file. Multiple tables per project are allowed and
   MERGE at runtime (Traktor's appendDictionary; last-loaded wins per key
   + a cook-time duplicate-key warning across tables).
3. **One cooked product carries all locales; the runtime selects.** Text
   is small (10k strings x 10 locales = low MB); per-locale product
   splitting is a size optimization DEFERRED until a real game needs it.
   This buys instant language switching with no load.
4. **Locale ids are BCP-47-ish strings** (`en`, `de`, `ja`, `pt-BR`) with
   a dash-truncation fallback chain: `pt-BR -> pt -> <default>`. The
   project's DEFAULT LANGUAGE is a project setting (new versioned field;
   settings DataVersion bump); the runtime language starts there and can
   be switched live.
5. **The service is a Context subsystem** (`LocalizationSubsystem`): owns
   the loaded tables + the active language, one per Context - which means
   PIE tabs sharing the embedded runtime share a language. Per-GameInstance
   language is NOT supported (no real use case; note the limitation).
   Registered in the standard batteries path (DefaultApplication +
   RegisterAllScriptFacades root - the drift lesson).
6. **Format = positional `{0}`-style substitution with natural types**
   (i32/i64/f32/f64/String - the Traktor Format model, minus wchar). NO
   plural rules, NO gender, NO number/date locale formatting in this
   track (CLDR/ICU-class problems; see Deferred). A `{n}` that names a
   missing argument renders literally (visible, greppable).
7. **UI markup opt-in via `@key`**: a text-bearing `.sml` attribute whose
   value starts with `@` is a localization key (`text="@menu.play"`);
   `@@` escapes a literal leading `@`. Resolution happens at document
   INSTANTIATION, and the resolved views remember their key so a language
   switch re-resolves in place (no re-instantiation). Cook-time: the
   UIDocument builder validates `@keys` against the project's string
   tables and WARNS on missing (not an error - text often lands after
   layout).
8. **Language switch is an event**: `SetLanguage` re-resolves live UI text
   and emits `languageChanged` on the run-scope bus (messaging cadence
   rules apply - arrives next frame) so game code can re-render anything
   it composed manually.
9. **Script surface: one curated static view** (the script-surface-verdict
   idiom - a static view, not subsystem reflection), prelude name `loc`:
   `loc::text("menu.play")`, `loc::format("hud.lives", n)`,
   `loc::language()`, `loc::setLanguage("de")`, `loc::has("key")`.
   AngelScript scope-resolution / Luau dot per the facade-syntax rules;
   natural types; kSubsystemFacadeNameCount +1.

## Module layout (house convention)

- `Code/Foundation/I18N` - module `foundation.i18n`, alias
  `Foundation::I18N`. Pure logic, Core-only deps: `StringTable` (locale
  column set + key -> per-locale UTF-8 text; hash-indexed), `Localization`
  (merged tables, active language, fallback-chain resolve, format
  substitution, once-per-key miss warning). No resource, no UI, no RHI -
  headless-testable.
- `Code/Foundation/I18N.Resource` - module `foundation.i18n.resource`.
  Cooked string-table resource + factory (`Ref<StringTable>` points
  here). CPU-only (no GPU factory - model B trivially).
- `Code/Pipeline/I18N.Pipeline` - `StringTableAsset`: locale list + rows
  (key + per-locale text). Source is XML per the text-scenes rule; text
  volume is human-authored, NOT machine-gen bulk, so it stays INLINE in
  the asset XML (the bulk-data sidecar rule does not trigger; revisit only
  if a table ever crosses the size threshold). Builder cooks asset ->
  resource; duplicate-key-across-tables warning lives here. CSV IMPORT +
  EXPORT (the translator round-trip; Traktor precedent - XLSX deferred):
  import = drag-drop importer (kImporterCount +1) AND a re-import action
  on the page; export = a page action writing `key,en,de,...` CSV.
  kBuilderCount +1 with tripwire.
- `Code/Engine/Engine.I18N` - module `engine.i18n`.
  `LocalizationSubsystem` (owns Localization, loads every cooked string
  table in the content set at startup - tables are FOUND, not referenced
  per-scene: text is a project-wide concern like input maps),
  `SetLanguage/Language`, the `languageChanged` emit, the `loc` facade
  registrar (joins RegisterAllScriptFacades), and the UI re-resolve hook
  (below).
- `Code/Editor/Editor.I18N` - the StringTablePage: GridView, rows = keys,
  columns = locales, editable cells, add/remove/rename key, missing-cell
  highlight, key filter box, CSV import/export actions, per-locale
  completeness count in the footer. New-asset creator entry. displayName +
  category attributes; open-by-instance like other bespoke pages.

## UI integration

`@key` resolution is a UI.Gamekit-level concern (game UI), NOT
foundation.ui: the document instantiation path (gamekit screens + world
UI documents) consults the LocalizationSubsystem when a text property
value starts with `@`. Views that resolved a key keep `{view, key,
property}` in a per-context re-resolve list owned by the subsystem
(pointer-safe: entries drop on view destruction via the existing
teardown seams); `SetLanguage` walks it. Editor-side UI pages
(UIDocumentPage preview) resolve through the same path when the embedded
runtime hosts them, so authored screens preview localized. Programmatic
text (Toast.message, MenuList items built from script) goes through
`loc::text` in the script - no magic there.

## Fonts (the CJK reality - P3 of this track)

MSDF/atlas font bakes enumerate codepoints, and CJK locales cannot ship
the full set. P3 adds a FontAsset option "charset from string tables":
at cook, the font builder scans the project's string-table products for
every codepoint used by the selected locales and bakes exactly those
(plus the asset's explicit ranges). Depends on nothing new - the builder
reads sibling products the way UI cooks read stylesheets. Until P3,
projects hand-list ranges (status quo). Editor font is untouched
(codepoints <= 255 rule stands - editor stays English).

## Phasing

- **P1 - the chain**: foundation.i18n + resource + pipeline (XML asset,
  cook, merge, fallback, format) + LocalizationSubsystem + `loc` facade
  (both backends) + project-setting default language (settings dialog
  field + DataVersion bump). Tests below. No editor page yet (New Asset +
  XML hand-edit suffices to exercise).
- **P2 - authoring**: Editor.I18N grid page + CSV import/export +
  UIDocument `@key` resolution + cook-time key validation warnings +
  live-switch re-resolve + `languageChanged` event. PaperKid dogfoods (menu
  screens move to `@keys`; a second locale added as the acceptance demo).
- **P3 - fonts**: charset-from-string-tables font bake option.

## Tests (required per phase)

- P1: lookup hit/miss-returns-key, fallback chain (`pt-BR->pt->default`),
  multi-table merge + last-wins + duplicate warning, format substitution
  (each natural type, missing-arg renders literally, `{{` escape), CSV
  import/export round-trip at the pipeline layer, cook round-trip
  (XML asset -> product -> resource matches source), facade calls through
  BOTH script backends (AngelScript + Luau), subsystem language switch +
  bus event cadence (emit frame N, arrive N+1 - messaging fixture
  precedent).
- P2: `@key` resolve at instantiation, `@@` escape, language switch
  re-resolves a live document (and a destroyed view drops from the
  re-resolve list - ASAN battery for this landing: lifetime-sensitive),
  cook warning on a missing `@key`.
- P3: baked font contains exactly the union charset for selected locales
  (fixture table with CJK), explicit ranges still honored.
- Tripwires: kBuilderCount, kImporterCount, kSubsystemFacadeNameCount
  (+1 `loc`), settings DataVersion gate test.

## Explicitly deferred

Per-locale cooked product splitting (size optimization); plural/gender
rules (CLDR-class; format args cover counts until a real game hurts);
number/date/currency locale formatting; RTL + bidi + complex shaping
(a fonts/text-shaping track prerequisite - the current shaper is
simple LTR; do not fake it with string reversal); XLSX dictionary format
(CSV covers the round-trip; Traktor has XLSX if we ever want it);
machine-translation helper (Traktor's Translator - editor nicety, not
engine work); per-GameInstance language; editor UI localization.
